# RSI v1 Implementation Plan

**Goal:** Evaluate autonomous momentum research in frozen worlds and safely activate at most one improved research policy per explicit cycle.

**Spec:** `docs/rsi-v1-spec.md`

**Architecture:** Reuse the actual bounded ReAct loop, research profile/report instructions, independent verifier rules and conservative merge, PolicyStore, FailureBundle, and candidate generator. Inject evaluation-only frozen tools. Separate the public world from hidden scoring facts; freeze profiles and controls once per experiment. Keep production tools and profile allowlists unchanged.

**Constraints:** No new agents/profiles/tools/frameworks in the application; no live internet for world observations; no autonomous commits; one candidate and one activation maximum; no active pointer changes until the audit artifacts and promotion gates pass. Existing session snapshots remain authoritative on resume.

## Tasks

- [x] 1. Frozen worlds: typed public and hidden data, content hashes, deterministic search/read/engine adapters; four documented synthetic momentum scenarios, approval manifest; authorization, timestamp, isolation and tamper tests.
- [x] 2. Capability mining: bounded deterministic taxonomy from session gaps/reports/task board/traces; occurrence IDs and hashes; existing-world mappings or pending review artifacts; no self-approval or automatic improvement.
- [x] 3. Arena: real ReAct planning, research and at most one requested replan; independent bounded verifier using the same frozen world; isolated sessions, explicit request/output/total token/tool/time limits and model records. Persist prompts, tool traces, terminal reports and verifier results. Hidden expectations only reach scorer.
- [x] 4. Outcome scoring and comparison: explicit independently VERIFIED grounded claims, required fact coverage, contradiction and withholding checks, per-world safety vetoes, hash/model/control/completion gates. Tests use the real loop with scripted external model responses, never a policy simulator in production.
- [x] 5. RSI cycle and CLI: select OPEN-gap targets plus fixed guards, baseline, failure bundle, existing one-shot generator, validated immutable candidate, paired arena results, auditable decision before activation under improvement lock. Tests cover all twelve requested acceptance paths and rejected/error pointer preservation.
- [ ] 6. Verification: full existing suite, focused safety tests, end-to-end deterministic demonstration artifacts; review code and document limits. A scripted transport demonstration proves wiring, not live model capability improvement.

## Decisions

Work on `codex/rsi-capability-arena` in the shared checkout so all requested edits remain reviewable without committing. The only pre-existing untracked path is `fixtures/engine/outputs/`; leave it untouched.

Use the subagent-driven-development skill for independent world/mining tasks while implementing arena integration locally. User specification and developer authorization override extra skill approval/commit ceremonies.

Public delivery contracts describe report shape and scope, never target sources or hidden expected facts. Fixture truth is synthetic and explicitly labeled; frozen engine results cannot claim live V_D delivery. Existing offline engine guards must independently pass before promotion.
